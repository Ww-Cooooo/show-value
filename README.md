# Show Value · 讲清产品价值

**你负责做产品，它帮你把好在哪儿讲清楚。**

项目已经做出来了，介绍时却总觉得漏了什么？这个 Skill 让正在协作的 AI 结合开发讨论、当前实现和已有演示，整理一份完整产品介绍，同时留下亮点依据、设计取舍和演示思路。后续写 README、做产品视频或准备发布介绍，都有材料可用。

它适合自己开发产品、却不容易把产品价值讲清楚的人。Skill 是交给 Agent 使用的一套任务指导；实际读取资料和撰写内容的是你正在使用的 Agent。

## 先用一次

已有这个文件夹时，把其中的 **SKILL.md 完整交给产品的原开发对话**，再发送下面的请求即可试用，不必先安装。如果 Agent 不能读取文件，就把正文粘贴到对话中。

> 请按这份 Skill，结合你能访问的开发记录和当前项目资料，整理完整产品介绍、重要亮点的依据、值得展示的细节和演示思路。结果用于介绍产品，输出中文。资料不够的地方请明确指出，不要补写成已经实现的能力。

一个对话有多个项目时，补上这次要介绍的项目名或路径。首次调用应看到两部分成果：面向读者的介绍，以及供作者继续策划内容的依据材料。有文件权限时保存在指定位置或项目内的“产品介绍资料”；否则直接在聊天中给出。

想先看成品是什么样，打开 [完整虚构示例](examples/完整示例.md)。示例含输入背景、可运行的小程序和完整交付，便于照着试；它不是客户案例或效果证明。

## 长期使用：放入你的 Agent 技能目录

将整个 **show-value** 文件夹放到对应目录。下表给出本地客户端的项目级安装位置，路径从你要分析的项目根目录开始：

| Agent | 安装后应存在的文件 | 在项目对话中调用 |
|---|---|---|
| Codex | `.agents/skills/show-value/SKILL.md` | `$show-value`，后面接具体请求 |
| Claude Code | `.claude/skills/show-value/SKILL.md` | `/show-value`，后面接具体请求 |
| 其他支持 Agent Skills 的工具 | 按该工具的技能目录说明放置 | 使用它自己的调用方式 |

例如使用 Codex，应把下载得到的 show-value 文件夹放进项目的 .agents/skills 文件夹，不能只复制一个外层压缩包。目标已有同名 Skill 时，先比较版本，不直接覆盖。

希望多个项目共用时，Codex 的用户级目录为 `~/.agents/skills/`，Claude Code 为 `~/.claude/skills/`；`~` 指当前用户的主目录。选择项目级或用户级的一处安装即可，避免同名版本混淆。

安装后在技能选择器中检查是否出现 show-value，再发送前面的试用请求。如果当前会话没有识别，仍可直接读取 SKILL.md；请保留原开发会话，不为刷新列表丢掉开发背景。

以上位置与调用方式依据 [Codex 官方说明](https://learn.chatgpt.com/docs/build-skills) 和 [Claude Code 官方说明](https://code.claude.com/docs/en/skills) 核对。云端会话可能使用独立工作区或账户级技能设置，不能照搬本机目录。

## 它会找出什么

它先梳理产品的主要使用流程，再沿相关实现和讨论寻找有价值的细节。比如，导出的内容能否继续编辑、一次操作后能否直接交给下一环节、某次改版为什么保留了一个看似不起眼的选项。具体价值取决于产品本身，不预设每个项目都有同一批优点。

每个重要亮点都要讲清：产品做了什么、对谁有用、依据在哪里、有哪些条件，以及怎样演示才看得出来。方案讨论、当前实现、实际用过和已经发布，会分别核对。

| 成果 | 主要内容 | 适合交给谁 |
|---|---|---|
| 产品介绍 | 用途、适用对象、主要优势、影响选择的条件；写成连贯的普通文案 | 目标读者；对外使用前由作者核对 |
| 亮点与演示依据 | 能力概貌、证据位置、开发取舍、主打建议、演示动作、内容角度及关键缺口 | 作者和获准接收内部资料的协作者 |

第二份材料可能包含未公开实现与内部讨论，不能因为第一份适合对外介绍，就把整套材料直接公开。Skill 不主动联系别的对话或发布渠道。

它不直接模仿某个作者的语气，也不默认生成短视频口播稿。需要口播、广告或特定平台内容时，再用这些资料提出下一项请求。

## 换个人、换项目或换工具，怎么用

| 手头有什么 | 可以怎样开展 |
|---|---|
| 原开发对话与仓库 | 同时理解设计原因并核对当前实现，是较完整的起点 |
| 只有仓库 | 提炼当前功能与使用价值；不猜作者当时的动机 |
| 只有说明、截图或开发讨论 | 整理资料支持的介绍；不声称检查过代码或亲自运行过 |
| 普通网页聊天工具 | 提供 Skill 正文和必要项目资料，在聊天中取得结果 |
| 云端 Agent | 先让当前工作区能访问项目或附件；本机路径不会自动上传 |

**换走的是方法，不会连同原开发会话的历史一起搬走。** 新会话或子 Agent 看不到的背景，需要提供相关记录。材料不完整时仍可先整理已知部分，关键缺口再补。

输出语言跟随用户要求；没有指定时沿用当前交流语言。方法不依赖固定作者、操作系统、仓库结构或长期记忆框架。

## 依赖、数据与当前验证范围

- Skill 本身只有指导文档和可选界面元数据，没有必装运行时、安装脚本、额外 API 或固定模型依赖。示例中的 Python 程序只用于演示，不是运行 Skill 的依赖。
- Agent 需要能理解资料；检查源码需要相应读取能力，验证运行效果还需要项目自己的环境。安装 Skill 不会增加读取权限或恢复不可访问的历史。
- Skill 不自带数据上传服务。你提供的资料仍会按宿主 Agent 和模型服务的规则处理；使用云模型不等于资料全部留在本机。不要提供密钥或无关私密文件。
- 资料整理不要求修改产品代码、配置或发布状态。需要保存成果时只创建任务文档；已有文件冲突先确认。
- 本机 Codex 已识别此前的调用版本。当前候选通过直接读取 SKILL.md，在本机独立子 Agent 中试跑了两个虚构案例：有实现与开发记录的中文项目，以及只有说明、无法保存文件的英文项目；产出已回看核对。尚未用真实产品验证提炼效果，也未测试候选的自动调用。
- 当前候选沿用 [Agent Skills 标准格式](https://agentskills.io/specification)。其他 Agent 的安装方式按官方文档整理，尚未逐个平台实际运行。普通聊天粘贴正文也不等于原生技能安装。
